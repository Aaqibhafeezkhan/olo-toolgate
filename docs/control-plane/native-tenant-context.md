# Console-scoped native requests

Chrome health and enrollment requests now carry the requesting console URL. The native host sends the closed v2 `ConsoleClientRequest` model, identified by `kind: console-tenant-state`, through authenticated local IPC. It does not call the general tray/CLI health or enrollment operation. The service holds its state lock while checking the protected installation origin and optional expected tenant UUID, then reads health or starts enrollment. A rejected context returns only the correlated tenant error; it exposes no health, enrollment prompt, activity, connection list or power state and does not mutate the journal.

The authorized origin is the protected configured HTTPS server origin, the exact configured loopback Quickstart console origin, or a signed v2 audience in the protected verified journal. Scheme, hostname and port all matter. An expected UUID is compared to the protected UUID anchor established by verified installer discovery or live v2 verification. Missing UUID state cannot satisfy an assertion. Chrome retains an optional `expectedTenantId` across its Connect session and passes it through the native host; malformed or conflicting assertions expose no device state. It is never authentication or a reason to create/switch tenants.

Browser Connect checks an existing protected configuration before fetching setup metadata or invoking elevated configuration. A foreign console or a different advertised Control origin produces `TENANT_MISMATCH`; the browser cannot implicitly switch the installed client to that destination. Matching-origin repair retains enrollment and key custody. A changed local CA requires explicit uninstall and purge; the installer cannot reset identity state to accept a recreated organization. A revoked device uses the service's governed approval request, retaining its identity anchor and awaiting Control approval.

The protected journal uses format version 3. The service acquires its OS lease and validates persisted state before loading or generating a key or constructing transport. A fresh journal binds the configured HTTPS origin and any administrator-pinned `tenantId` before key creation. Installer setup obtains that UUID from HTTPS-authenticated, verified v2 discovery. The first cryptographically verified discovery binds its canonical tenant UUID before the service requests enrollment. Initial anonymous presence is constrained to the configured origin; after binding, HTTP presence/discovery/enrollment and protected requests carry the UUID assertion. The transport accepts only one UUID for its lifetime. The UUID survives deletion/revocation recovery, enrollment resets and restarts. Another origin, another UUID, an unsupported journal, or an orphan key fails without rewriting the journal or key. Pre-release state is unsupported; there is no journal or parked-profile conversion.

One installation runs one tenant connection. The runtime no longer opens saved background profiles, and the installer no longer parks, restores or retires another tenant's journal. Uninstall retains its tenant state by default. Explicit `uninstall --purge` deletes the device key as well as enrollment and local data, so another organization receives a fresh key. Live discovery uses v2 only; discovery trust and manifest are stored together. TLS bootstrap roots and signed tenant device authorities are separate. Unsupported local state is refused rather than upgraded.

Successful native health/enrollment replies carry the validated `consoleOrigin`. Error replies do not append another installation's server URL. The extension requires that origin to match its requesting tab, passes the console on every health/enrollment call, and treats tenant mismatch as a stopped connection attempt. It removes cached codes, does not probe health or trigger enrollment/repair after mismatch, and does not reinterpret the failure as a missing installation. Session checks discard health, enrollment and proof replies after cancellation or replacement of that connection attempt.

The console stops polling on tenant mismatch, clears a previously displayed code, hides setup links and gives an organization-URL message. It does not automatically retry Connect for this error. Availability probes remain public extension/version information and do not query local device state.

These are independently enforced native/service boundaries. Discovery v2, immutable UUID configuration and Gateway binding are implemented together. See the [deployment qualification guide](../deployment/multitenant.md) for the native installer matrix, source-bound artifacts and operational rollout requirements.
