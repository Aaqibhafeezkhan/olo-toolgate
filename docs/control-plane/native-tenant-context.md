# Console-scoped native requests

Chrome health and enrollment requests now carry the requesting console URL. The native host sends the closed v2 `ConsoleClientRequest` model, identified by `kind: console-tenant-state`, through authenticated local IPC. It does not call the general tray/CLI health or enrollment operation. The service holds its state lock while checking the protected installation origin and optional expected tenant UUID, then reads health or starts enrollment. A rejected context returns only the correlated tenant error; it exposes no health, enrollment prompt, activity, connection list or power state and does not mutate the journal.

The authorized origin is the protected configured HTTPS server origin or the exact configured loopback Quickstart console origin. Scheme, hostname and port all matter. An expected UUID is an assertion compared to the verified stored manifest, never authentication or a reason to create/switch tenants. Missing verified UUID state cannot satisfy an asserted UUID. During the remaining v2 cutover, signed audiences and the immutable UUID installation binding must extend this check for approved distinct Gateway/Control origins.

Browser Connect checks an existing protected configuration before fetching setup metadata or invoking elevated configuration. A foreign console or a different advertised Control origin produces `TENANT_MISMATCH`; the browser cannot implicitly switch the installed client to that destination. Same-origin, explicitly requested repair remains supported. The general installer/parked-profile implementation has not yet been removed and is not a claim of final single-tenant installation binding.

Successful native health/enrollment replies carry the validated `consoleOrigin`. Error replies do not append another installation's server URL. The extension requires that origin to match its requesting tab, passes the console on every health/enrollment call, and treats tenant mismatch as a stopped connection attempt. It removes cached codes, does not probe health or trigger enrollment/repair after mismatch, and does not reinterpret the failure as a missing installation. Session checks discard health, enrollment and proof replies after cancellation or replacement of that connection attempt.

The console stops polling on tenant mismatch, clears a previously displayed code, hides setup links and gives an organization-URL message. It does not automatically retry Connect for this error. Availability probes remain public extension/version information and do not query local device state.

These are independently enforced native/service boundaries. The remaining coordinated discovery v2, immutable UUID configuration, installer and Gateway cutover is still required; this change does not enable shared production tenant hosting.
