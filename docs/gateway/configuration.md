# Gateway configuration

Gateway uses current online Control authority for discovery, invocation creation, dispatch and result retrieval. It has no local permission policy, extractor, approval signer or offline ALLOW cache. [Group authorization](../security/enterprise-access-control.md) defines the decision model.

`TOOLGATE_GATEWAY_CONFIG` and `TOOLGATE_GATEWAY_CREDENTIALS` select administrator-mounted bounded JSON files. Unknown fields and invalid, expired or ambiguous credentials reject startup. The [online example](../examples/gateway-online.json) contains routing and capacity configuration only. Supply a Control HTTPS origin and a protected, separately refreshed service JWT file. Only explicit development fixtures may use `developmentLoopbackHttp=true` with a numeric loopback origin.

Each Gateway process serves exactly one provisioned tenant. Set `control.tenantId` to its canonical UUID and `tenantHosts` to 1–16 explicit HTTP authorities owned by that tenant, including non-default ports where needed. There is no alias or default-tenant fallback. Every mounted credential must name that UUID; a foreign credential rejects startup, and a foreign reload leaves the previous credential set intact. The Control relay sends the expected UUID with its separate service credential and refuses a foreign request context before reading that credential.

The runtime checks Host/HTTP authority before authentication or authority calls. Unknown hosts return `404 TENANT_UNAVAILABLE`; conflicting or duplicate authorities return `421 MISDIRECTED_REQUEST`. The optional `Toolgate-Tenant-ID` header is an assertion: malformed/duplicate values return `400 INVALID_TENANT_ID`, and a foreign UUID at a configured host returns `403 TENANT_MISMATCH`. Its absence is allowed. Forwarded headers cannot select a tenant or credential. Preserve the original Host at the trusted TLS proxy; explicitly list any dedicated internal authority used by private loopback callers. The two anonymous GET routes `/.well-known/olo-toolgate-client` and `/api/public/v1/clients/configuration` use the same host and optional UUID guards. All other routes retain their normal authentication.

Configure `publicDiscovery: {controlOrigin, gatewayOrigin}` with exact canonical HTTPS origins. `controlOrigin` must equal `control.url`; `gatewayOrigin` must belong to `tenantHosts`. The Gateway fetches discovery from this fixed Control origin using an anonymous TLS client with no service JWT, redirects or proxy. It verifies the v2 signature, tenant UUID, both origins and monotonic key generation before returning it. Configuration returns only the verified Control URL. Unknown or suspended Control tenants return the same public 404; cached metadata cannot authorize them. For a private TLS CA, set `control.caCertificatePath` to its public PEM file (Helm: `gateway.control.caSecret`). Preserve the canonical Control Host and TLS SNI on private routing, using DNS or a trusted proxy. A forwarded header never chooses a credential or tenant.

Devices retain their own durable discovery trust floor; Gateway public trust caching is process-local. Both device and Gateway refresh from independently authenticated fixed-origin HTTPS when they encounter an unknown signing key, and reject rollback, known retired signers and origin/tenant changes. This does not reload TLS trust roots: distribute public TLS/client-CA roots before activating certificates that need them.

Each credential contains `tokenSha256`, a canonical `RequestContext`, and `expiresAtUnixMs`. The context binds tenant, SERVICE or DELEGATED mode, `credentialKind: "STATIC_TOKEN"`, Agent, workload binding, credential epoch/digest and execution binding; delegated mode also binds verified User/session and chain. The context names no device: Control places each call on one online device of the execution binding's device group (the caller's own device first, otherwise the least-loaded member, so a pool of executor containers shares the work). A context `expiresAtUnixMs`, if present, must equal the credential's; the Gateway fills it in. Use independently generated high-entropy tokens. Mounted facts authenticate the caller; the current enabled workload binding and complete group grants in Control determine access. A device approval creates no agent credential. Configure workloads through reviewed administration before calling tools.

`toolHosts` lists the Tool Hosts this Gateway dispatches to, as `{hostId, url}`: the host's enrolled device id and its loopback dispatch origin (at most 64). When Control places a call on one of them, the Gateway asks Control for a signed permit for that host (`POST /api/control/v1/access/invocations/reserve` with `audience`, `attempt` and the exact `arguments`), posts the permit and arguments to the host's `/v1/dispatch` and returns the host's result. When Control issues a permit for a host that is not listed, the Gateway hands the dispatch to Control (`POST /api/control/v1/access/dispatches`); the host fetches it in pull mode and the Gateway follows its status. A call Control answers 409 for (placed on an enrolled client rather than a Tool Host) goes through the device relay. See [Tool Host](../../apps/tool-host/README.md) and the [API reference](../api/api-reference.md#toolscall).

Runtime binds loopback unless `trustedTlsProxy=true`. This flag asserts a deployment boundary: use trusted TLS termination and restricted network peers. Forwarded headers never establish caller identity. Management probes and metrics have a separate restricted listener. CORS accepts only configured exact HTTPS origins.

| Limit | Default |
|---|---|
| Request body / headers | 64 KiB / 8 KiB |
| Concurrent requests / connections | 128 / 256 per replica |
| Ingress rate | 1,000 per second per replica |
| Request / connection deadline | 20 / 35 seconds |
| Shutdown drain | 35 seconds |
| Audit queue | 256 entries |

Ingress capacity limits are independent of durable group execution budgets. Control evaluates current authority immediately before protected effects. Permits last at most ten seconds, have zero clock grace, are purpose-bound and single-use. Cached discovery creates no execution right. Readiness polls authenticated current Core authority every five seconds; an outage removes readiness and blocks new effects.
